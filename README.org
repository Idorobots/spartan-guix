* Spartan Guix

A GNU Guix channel for reusable packages, services and Raspberry Pi images.

With the channel configured in =channels.scm= and =guix pull= completed, install
packages normally:

#+begin_src sh
guix install klipper moonraker mainsail nut
#+end_src

Import the corresponding modules in your Guix System configuration to use the
services.

** Inventory

(incremental uploads), =python-preprocess-cancellation= (G-code object markers)
and =python-periphery= (Linux peripheral I/O).

*** Firmware

=(spartan packages firmware)= provides:

- =linux-firmware-uncompressed=: Nonguix's firmware collection in uncompressed
  form, including Pi 3 Wi-Fi firmware, board configuration and regulatory data.
  Suitable for kernels without firmware compression support.
- =rpi3-bluetooth-firmware=: version-pinned Debian BCM43430A1 firmware and its
  Cypress license, with the =BCM43430A1.raspberrypi,3-model-b.hcd= alias.

Both install under =lib/firmware/=. Pi 2 and Pi 3 include the uncompressed
Linux firmware collection; Pi 3 additionally includes its Bluetooth firmware.

*** Seeed Studio 7-inch HDMI display

=(spartan packages displays)= provides =seeedstudio-7inch-hdmi-config=: exact
720×1280 panel timings for native Pi 3 VC4/KMS. Opt in from a system definition:

#+begin_src scheme
(use-modules (gnu system images raspberrypi) (spartan system displays))

(with-seeedstudio-7inch-hdmi-display rpi3-barebones-os
  #:connector "HDMI-A-1" #:early-console? #t #:rotation 270)
#+end_src

The helper customizes the selected kernel to enable EDID overrides, using the
panel's exact 70 MHz timings even without a usable panel EDID. VC4 is the Pi's
display driver; KMS lets Linux set display modes. By default, EDID loads through
Guix firmware activation before udev loads VC4. =#:early-console? #t= additionally
embeds the EDID and enables console rotation; it does not load VC4 earlier.
Use =#:custom-kernel? #f= only with an EDID-capable kernel and VC4 loading after
activation. Graphical rotation and USB touch alignment belong to the application
or compositor. See the [[https://docs.google.com/viewer?url=https://github.com/SeeedDocument/Pi_screen/raw/master/Instructions_for_use.pdf][Pi 3 instructions]], [[https://github.com/SeeedDocument/wiki_english/blob/master/docs/720x1280%20HDMI%20IPS%20LCD%20Display.md][Seeed configuration guide]] and
[[https://www.seeedstudio.com/7-inch-720x1280-HDMI-IPS-LCD-Display-p-2861.html][display specifications]].

For filesystem growth, reference a filesystem already declared in the host:

#+begin_src scheme
(use-modules (gnu services) (spartan services file-systems))

(service resize-file-system-service-type
         (resize-file-system-configuration
          (file-system data-file-system)))
#+end_src

Supports ext2/3/4, Btrfs and bcachefs on plain partitions with adjacent free
space. Each instance runs after its filesystem is mounted; LVM and multi-device
filesystems are outside its scope.

** Klipper

Klipper 0.13.0 includes compiled host helpers, MCU sources, configurations and
flashing tools. Supply a printer-specific configuration to the Shepherd service:

#+begin_src scheme
(use-modules (gnu services) (guix gexp) (spartan services klipper))

(service klipper-service-type
         (klipper-configuration
          (config-files (list (cons "printer.cfg" (local-file "printer.cfg"))
                              (cons "config.d/macros.cfg" (local-file "macros.cfg"))))
          (firmware-workspace? #t)))
#+end_src

=config-files= is an alist of =(relative-path . file-like)= pairs seeded below
the writable state directory. It must contain =printer.cfg=; its position in
the alist doesn't matter. Add =[include config.d/macros.cfg]= to =printer.cfg=
to load the example fragment; Klipper's include lines control load order.
Destinations must be unique, with no empty, =.=, or =..= path components, and
cannot conflict with =klippy.log=. Activation copies only missing files and
preserves edits and =SAVE_CONFIG= calibration. Klippy runs as =klipper= with
=dialout= access; arrange the board's device permissions on the host.

- =state-directory=: =/var/lib/klipper=; holds the configuration and log.
- =run-directory=: =/run/klipper=; holds =klippy.sock= and the =printer= PTY.
- =firmware-workspace?=: default =#f=. Enables a writable source/tools copy at
  =/run/klipper/firmware=, following =run-directory= overrides. It survives
  reconfiguration, including =.config= and build outputs, but is refreshed after
  reboot. Save wanted files outside =/run=; disabling the flag leaves an existing
  workspace until reboot.

Directory overrides must be distinct absolute service paths outside the store,
without dot components; repeated and trailing slashes are normalized.

With =make=, the board's compiler and flash utility installed:

#+begin_src sh
sudo -i
cd /run/klipper/firmware
make menuconfig
make
#+end_src

The tools use the packaged Python environment. =scripts/flash-sdcard.sh= defaults
to the workspace's =out/klipper.bin= and =out/klipper.dict=; the installed
=klipper-flash-sdcard= command accepts =-l= to list boards and =-f= / =-d= to select
firmware/dictionary files. Workspace preparation does not build or flash firmware.
Stop Klippy with =herd stop klipper= before flashing and restart it with
=herd start klipper= afterward. Follow the board's bootloader/SD-card procedure.

** Moonraker

Moonraker 0.11.0 supplies the printer API, uploads, metadata and history. Its
package includes Shepherd provider 0.1.0 and the compatibility patch. It can be
installed independently of Klipper.

Use one configuration object for the service and its exact sudo permissions:

#+begin_src scheme
(use-modules (gnu services) (gnu system) (spartan services moonraker))

(define moonraker-config (moonraker-configuration))
(define printer-api (service moonraker-service-type moonraker-config))
(define printer-sudoers
  (moonraker-sudoers-file moonraker-config %sudoers-specification))
#+end_src

Add =printer-api= to the OS's =services= and set =sudoers-file= to
=printer-sudoers=. Pass the host's existing sudoers file in place of
=%sudoers-specification= when customized. The composer preserves it and adds
exact =NOPASSWD: NOSETENV:= helper commands; Guix validates the result with
=visudo=. The service alone does not install sudo permissions.

Declare Klipper separately: it supplies the shared =klipper= account. Moonraker
starts after networking and reconnects to Klippy independently, so stopping
Klipper leaves the API available. Do not add =klipper= to its
=shepherd-requirement=.

| Setting | Default / use |
|---------+---------------|
| =config-files= | Alist of relative names to file-like objects or absolute runtime paths. Requires =moonraker.conf=, which defaults to =%moonraker-default-config=. |
| =data-directory= | =/var/lib/moonraker=; uploads, logs, database and communications, owned by =klipper= with mode =0750=. |
| =klipper-state-directory= | =/var/lib/klipper=; linked as the API's writable =config= directory. |
| =managed-services= | ='(("klipper" start stop restart) ("moonraker" restart))=; complete service/action allowlist. |
| =power-actions= | ='(poweroff reboot)=; use ='()= to disable power controls. Also supports =halt=. |
| =shepherd-socket= | =/var/run/shepherd/socket=. |
| =shepherd-timeout= | 60 seconds; finite and positive. Submitted actions may finish after a timeout. |
| =shepherd-requirement= | Additional prerequisites, such as ='(sops-secrets)= for runtime configuration. |

The default listens on =0.0.0.0:7125= and connects to =/run/klipper/klippy.sock=.
It allows CORS for =*.local= and =localhost=, including explicit ports, and trusts
private, loopback and link-local networks, including IPv6 unique-local addresses.
Trusted clients have full API access. Forwarded client-IP headers are disabled;
OctoPrint compatibility is enabled and object preprocessing is disabled.

The service lays out the named files in a store directory and loads
=moonraker.conf= from that tree. Use native includes such as
=[include conf.d/authorization.conf]= to load other entries. Relative includes
resolve from the including file's named location in the tree; later includes
override earlier settings. The generated wrapper adds its authoritative
=[machine]= settings after the application configuration. Don't include the
same file twice. Provision absolute runtime sources before startup and add the
appropriate Shepherd prerequisite if needed. Keep =update_manager= disabled.

Reconfiguration preserves uploads, database and calibration and does not replace
an unmanaged =config= directory. Data and printer-state paths must be absolute,
outside the store and non-overlapping. Match directory/socket overrides to
Klipper's configuration.

Additional service entries can permit selected actions or status only, e.g.
=("camera")=. Keep the ="moonraker"= entry; it permits only =restart= or no
actions. The immutable policy limits authorized clients' controls;
=moonraker.asvc= cannot add rights. The helper rejects operations that would
stop Moonraker through dependencies. For halt, permit =halt= and set
=shutdown_action: halt= in the application file.

=moonraker-config-file= and =moonraker-shepherd-policy= expose the generated
files. The provider installs =bin/moonraker-shepherd= and the patch under
=share/moonraker-provider-shepherd/patches/=. See the
[[https://github.com/Idorobots/moonraker-provider-shepherd][provider documentation]] for its protocol and management semantics.

For printing uploaded files, include in the printer configuration:

#+begin_src conf
[virtual_sdcard]
path: /var/lib/moonraker/gcodes

[display_status]

[pause_resume]
#+end_src

** Mainsail

Mainsail 2.19.0 packages the official GitHub release ZIP with a pinned SHA-256.
Its static frontend is in =share/mainsail=, including =config.json=, service
worker, fonts, images and version metadata; the license is in
=share/doc/mainsail-2.19.0/LICENSE=. JavaScript runs in the browser, with no
Node.js runtime needed on the printer host. Updates are managed through Guix.

Add the default configuration to the host's nginx service:

#+begin_src scheme
(use-modules (gnu services) (gnu services web) (spartan services mainsail))

(service nginx-service-type %mainsail-nginx-configuration)
#+end_src

Following the [[https://docs.mainsail.xyz/setup/manual/][manual setup]], it serves Mainsail at the site root on IPv4 port 80:

- Immutable document root, SPA fallback, level-4 gzip and no-cache headers for
  =index.html=, =config.json= and =sw.js=.
- =/printer/=, =/api/=, =/access/=, =/machine/= and =/server/= proxy to
  =127.0.0.1:7125=, preserving URIs, queries and forwarding headers.
- =/websocket= uses HTTP/1.1 upgrades and a 86400-second read timeout.
- Uploads stream without nginx's size limit or request buffering; Moonraker's
  =max_upload_size= still applies.
- =/webcam/= through =/webcam4/= map to loopback ports 8080–8083, stripping
  prefixes and disabling stream buffering. Provision camera software separately.

Nginx starts independently of backends and uses standard Guix logging, runtime
directories and log rotation. Moonraker authorization still applies.

Customize with =mainsail-nginx-configuration=:

#+begin_src scheme
(use-modules (guix gexp))

(service nginx-service-type
         (mainsail-nginx-configuration
          #:server-name '("printer.local")
          #:webcams '("127.0.0.1:8080")
          #:config-file (plain-file "mainsail-config.json"
                                   "{\"defaultLocale\":\"en\",\"defaultMode\":\"dark\"}\n")))
#+end_src

Other keywords: =#:package= (provides =share/mainsail=), =#:listen= (default
='("80 default_server")=), =#:moonraker-address= (default ="127.0.0.1:7125"=)
and =#:gzip?= (default =#t=). =#:server-name= defaults to ='("_")=; add
="[::]:80 default_server"= to the listener list for IPv6. An empty =#:webcams=
list omits camera routes. =#:config-file= serves one file-like JSON override
as =/config.json=. The default, =#f=, serves the package's upstream file.

The result is a normal =nginx-configuration= record. Inherit it for global
settings; retain its server/upstream blocks and WebSocket map when combining
sites. Use the Klipper and Moonraker setup above for the printer backend.

** Network UPS Tools

NUT 2.8.5 includes USB, serial and SNMP drivers, OpenSSL support, =upsd= and
clients. Optional protocols without their libraries, such as Modbus/IPMI,
are omitted. Declare each UPS using a driver from the
[[https://networkupstools.org/stable-hcl.html][hardware compatibility list]]:

#+begin_src scheme
(use-modules (gnu services) (spartan services nut))

(service upsd-service-type
         (upsd-configuration
          (ups (list (nut-ups
                      (name "office")
                      (driver "usbhid-ups")
                      (port "auto")
                      (extra-config "vendorid = 051d\nserial = YOUR-SERIAL\n"))))
          (users-file "/run/secrets/upsd.users")
          (shepherd-requirement '(sops-secrets))))
#+end_src

Use unique UPS names; =port= defaults to =auto= and device =extra-config= extends
its =ups.conf= section. Each declared device gets a =nut-driver-NAME= service;
=upsd= starts after its drivers, networking and any =shepherd-requirement=.
Shepherd supervises processes; NUT reconnects to hardware.

The service creates the =nut= account, =/run/nut= and =/etc/nut=, installs the
package and adds upstream USB udev permissions. Arrange serial-device access
yourself; replug USB devices if they retain old permissions after deployment.

- =extra-config= supplies the whole =upsd.conf=, default =LISTEN 127.0.0.1 3493=.
  Add explicit listeners for LAN clients; =package= selects an alternate NUT.
- =users-file= is an absolute, runtime-managed credentials path, linked directly
  as =/etc/nut/upsd.users=. Make it readable by =nut=, with traversable parents,
  before startup. It need not exist on the build host and is not copied or
  permission-adjusted. Keep passwords out of store-backed configuration.
- Without =users-file=, status queries work but authenticated administration
  and =upsmon= login do not. Reload/restart =upsd= after credential changes.
  Automatic shutdown needs a separately configured =upsmon=.

In the example, provision the secret with SOPS and grant =nut= access (e.g.
group =nut=, mode =0640=), or choose another runtime path and prerequisite.
Inspect the service with =herd status upsd= and query =upsc office@localhost=.

** Raspberry Pi systems and images

=(gnu system images raspberrypi)= provides minimal ARMv7 Pi 2 v1 and ARM64 Pi 3
systems with DHCP, reference NTP (default server pool and initial clock
correction), nonfree runtime firmware and automatic root filesystem growth.
Both use non-deblobbed Linux: =linux-rpi2= from =(spartan packages raspberrypi)=
derives an ARMv7 kernel through Nonguix's =corrupt-linux= helper, and Pi 3 uses
Nonguix's =linux-arm64-generic=. The Pi 2 kernel retains =multi_v7_defconfig=
and provides an unqualified =bcm2836-rpi-2-b.dtb= alias for 32-bit U-Boot.
The SD layout is MBR, with a 256 MiB
FAT32 =PIBOOT= partition at =/boot/firmware= and the persistent ext4 =Guix= root
partition last on the card.

The firmware loads U-Boot, which reads =/boot/extlinux/extlinux.conf= from the
root filesystem and boots Linux/initrd. Guix maintains kernel arguments,
device-tree paths and previous generations. The bootloader installs firmware,
device trees and U-Boot as FAT-compatible files; =install-rpi-boot-files= is
available in =(spartan bootloader raspberrypi)= for custom image initializers.

| Export | Use |
|--------+-----|
| =rpi2-barebones-os= | Inherit to define a 32-bit Pi 2 v1 host. |
| =rpi2-barebones-raw-image= | Ready-to-build ARMv7 SD image. |
| =rpi2-image-type= | Discoverable as =rpi2-raw= in an installed channel. |
| =rpi3-barebones-os= | Inherit to define a Pi 3 host. |
| =rpi3-barebones-raw-image= | Ready-to-build SD image. |
| =rpi-image-type= | Discoverable as =rpi-raw= in an installed channel. |
| =%rpi-root-file-system=, =%rpi-boot-file-system= | Shared root/boot declarations. |
| =%rpi-resize-file-system-service= | Root partition/filesystem growth at boot. |
| =rpi3-package=, =rpi3-guile-fixes= | Pi 3 package adaptation and its Guile transformations. |

Build the Pi 3 SD image using the installed channel's =rpi-raw= image type:

#+begin_src sh
guix system image --system=aarch64-linux --image-type=rpi-raw \
  -e '(@ (gnu system images raspberrypi) rpi3-barebones-os)'
#+end_src

Build the Pi 2 v1 image from the same module with its ARMv7 image type:

#+begin_src sh
guix system image --system=armhf-linux --image-type=rpi2-raw \
  -e '(@ (gnu system images raspberrypi) rpi2-barebones-os)'
#+end_src

Both systems include =linux-firmware-uncompressed= and =%base-firmware=,
including =wireless-regdb=. Pi 3 also includes =rpi3-bluetooth-firmware=.
Supply Wi-Fi credentials, radio services and host-specific
provisioning in the consuming configuration. For added Guile-dependent packages,
import =(gnu system images raspberrypi)= and =(gnu packages guile)=, then use
the helper, e.g. =(rpi3-package guile-readline)=. Image construction and hardware
boot are separate deployment steps.

** Package helpers

*** Cortex-A53 workaround

=(spartan packages cortex-a53)= provides =guile-with-cortex-a53-fix= for Guile's
AArch64 erratum 843419 linker workaround. The Pi 3 OS already uses it:

#+begin_src scheme
(use-modules (gnu packages guile) (spartan packages cortex-a53))
(guile-with-cortex-a53-fix guile-3.0)
#+end_src

*** Compilation platform

=(spartan packages mixed)= provides =package-with-compilation-system=. It adapts
a package for compilation on a chosen platform while preserving the output
architecture requested by Guix. Use it to prepare AArch64 packages for a Pi on
an x86-64 build machine, for example. Pass a package and optionally =#:system=
to choose the compilation platform; the default is the Guix runner's platform.
Apply recipe changes before wrapping:

#+begin_src scheme
(use-modules (nongnu packages linux) (spartan packages mixed))
(package-with-compilation-system linux-arm64-generic)
(package-with-compilation-system linux-arm64-generic #:system "x86_64-linux")
#+end_src

*** Guile and dependency transformations

- =(spartan packages guile-snarf)=: =guile-with-native-snarf= adjusts Guile's
  installed preprocessor defaults.
- =(spartan packages guile-config)=: =guile-with-native-config= supplies a usable
  =pkg-config= for the installed Guile SDK.
- =(spartan packages guile)=: =make-guile-runtime-rewriter= returns a package
  transformation accepting =#:guile-transform=, =#:replacements= (package pairs)
  and =#:system=.

#+begin_src scheme
(use-modules (gnu packages guile) (spartan packages guile)
             (spartan packages guile-config) (spartan packages guile-snarf))
(define with-guile-sdk
  (make-guile-runtime-rewriter
   #:guile-transform (compose guile-with-native-snarf guile-with-native-config)))
(with-guile-sdk guile-readline)
#+end_src

Dependency helpers apply the named compatibility variants to a package's
dependencies. Import the module and call the helper with a package:

| Module | Helper |
|--------+--------|
| =(spartan packages compression)= | =package-with-cross-fixed-libcbor= |
| =(spartan packages groff)= | =package-with-cross-fixed-groff= |
| =(spartan packages gtk)= | =package-with-cross-fixed-pango= |
| =(spartan packages linux)= | =package-with-cross-fixed-alsa=, =package-with-cross-fixed-lm-sensors= |
| =(spartan packages maths)= | =package-with-cross-fixed-plotting= |
| =(spartan packages tls)= | =package-with-cross-fixed-perl-net-ssleay= |

For custom replacements, =(spartan packages cross)= exports
=package-input-rewriting/cross=: pass an alist of =(original . replacement)=
packages, then apply the returned procedure to a package. Recipe authors can
reuse =configure-cross-perl-phase= from =(spartan packages perl)= for Perl XS
configuration. When combining the Groff helper with the Guile rewriter, apply
Groff first: =(compose with-guile-sdk package-with-cross-fixed-groff)=.
